1. <div> vs <section>
<div> — Generic container

<div> has no semantic meaning. It simply groups elements together so you can style them with CSS, manipulate them with JavaScript, or organize your HTML.

<div class="card">
    <h2>John Doe</h2>
    <p>Web Developer</p>
</div>

The browser doesn't know that this is a "card." It just knows it's a generic container.

Use <div> when:
You need a container for CSS styling
You need to group elements for JavaScript
The group doesn't represent a meaningful standalone part of the document
There isn't a more appropriate semantic HTML element

Example:

<div class="container">
    <div class="row">
        <p>Hello</p>
    </div>
</div>

Here, the <div> elements are primarily being used for layout.

2. <section> — Meaningful section of content

<section> is a semantic HTML element. It tells the browser, screen readers, search engines, and developers that the content represents a distinct section of the page.

<section>
    <h2>Our Services</h2>

    <p>We provide the following services:</p>

    <ul>
        <li>Web Development</li>
        <li>UI/UX Design</li>
        <li>Database Management</li>
    </ul>
</section>

The important difference is that "Our Services" is a meaningful part of the document.

A <section> will generally have a heading:

<section>
    <h2>About Us</h2>
    ...
</section>

<section>
    <h2>Our Services</h2>
    ...
</section>

<section>
    <h2>Contact Us</h2>
    ...
</section>
Use <section> when:
You're dividing a page into thematic sections
The content has its own heading
The section could reasonably be described as a distinct part of the document
Quick comparison
<div>	<section>
Generic container	Semantic container
Has no inherent meaning	Represents a meaningful section
Mainly for layout/styling/JS	For organizing document content
Doesn't normally need a heading	Usually has a heading
No special accessibility meaning	Can contribute to document structure
Use when no semantic element fits	Use when content forms a distinct topic
Example

Bad use of <section>:

<section class="flex-container">
    <div>Item 1</div>
    <div>Item 2</div>
</section>

If this is simply a layout wrapper, <div> is more appropriate:

<div class="flex-container">
    <div>Item 1</div>
    <div>Item 2</div>
</div>

Good use of <section>:

<section>
    <h2>Student Projects</h2>

    <article>
        <h3>Mini Shop Website</h3>
        <p>A website built using HTML, CSS and JavaScript.</p>
    </article>
</section>
2. What are ARIA roles?

ARIA stands for Accessible Rich Internet Applications.

ARIA provides additional information to assistive technologies, especially screen readers.

For example:

<div role="button">Submit</div>

You're telling a screen reader:

"Treat this <div> as a button."

But there's an important rule:

Use native HTML semantics whenever possible instead of ARIA.

So this:

<button>Submit</button>

is better than:

<div role="button">Submit</div>

Why?

Because <button> already has built-in:

Button semantics
Keyboard behavior
Accessibility support
Focus behavior
Expected interaction

With the <div role="button">, you'd have to implement much of that behavior yourself.

4. When is ARIA actually needed?

ARIA becomes useful when you're creating custom UI components whose behavior isn't adequately represented by native HTML.
ARIA tells assistive technology:
This is a group of tabs.
This element is a tab.
This tab is currently selected.

ARIA provides information that isn't automatically available from a generic <div>.

4. zero non-semantic container elements where a semantic alternative exists. All images have meaningful alt text. All form inputs are associated with label elements via for/id.  
What your mentor is checking
No unnecessary <div> or <span>
Use <header> for introductory/site-header content.
Use <nav> for navigation.
Use <main> for the primary content.
Use <article> for the blog post.
Use <section> for meaningful subsections.
Use <aside> for related/sidebar content.
Use <footer> for footer content.
Use <figure> for figures/images with captions.
Only use <div> when no appropriate semantic element exists.

Every meaningful image has alt text

<img src="author.jpg" alt="Israel, the author of the article">

Decorative image:

<img src="divider.png" alt="">

Every form input has an associated <label>

<label for="email">Email address</label>
<input type="email" id="email" name="email">

The important part is:

label for="email"
           ↓
input id="email"

They must match.

Example: accessible blog subscription form
<section>
    <h2>Subscribe to our newsletter</h2>

    <form action="/subscribe" method="post">
        <p>
            <label for="name">Name</label>
            <input type="text" id="name" name="name">
        </p>

        <p>
            <label for="email">Email address</label>
            <input type="email" id="email" name="email" required>
        </p>

        <button type="submit">Subscribe</button>
    </form>
</section>

Notice that there is no unnecessary <div>.
