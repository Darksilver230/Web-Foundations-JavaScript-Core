1. git merge vs git rebase

Both are used to combine changes from one branch into another, but they do it differently.

Suppose you have:

main
  A---B---C
       \
        D---E
        feature

You want to bring feature into main.

git merge

You switch to main:

git checkout main

Then:

git merge feature

Git creates a merge commit:

A---B---C-------M
     \         /
      D---E---

M represents the merge commit.

Advantages
Preserves the actual history.
Doesn't rewrite existing commits.
Good for collaborative branches.
Safer when other people are already working on the branch.
When would you use merge?

Use it when you want to combine a completed feature branch into main while preserving the branch history.

For example:

git checkout main
git merge feature-login
2. git rebase

Rebase takes your commits and replays them on top of another branch.

Starting with:

A---B---C
     \
      D---E

If you run:

git checkout feature
git rebase main

Git effectively produces:

A---B---C---D'---E'

Notice D and E became D' and E'.

That's because Git created new versions of those commits based on the new starting point.

Why use rebase?

It gives you a cleaner, more linear history.

For example:

A---B---C---D---E

instead of:

A---B---C-------M
     \         /
      D---E---
When would you use rebase?

A common situation is updating your feature branch with the latest main:

git checkout feature
git fetch origin
git rebase origin/main

Now your feature work appears as if it was created on top of the latest main.

3. Important rebase warning

Rebase rewrites commit history.

So be careful rebasing commits that you've already pushed and that other people are using.

For example, avoid casually doing:

git rebase main
git push

on a shared branch.

You may need a force push after rewriting history:

git push --force-with-lease

--force-with-lease is safer than plain --force, but you should still understand why you're rewriting the branch.

Easy rule

Merge = preserve history.

Rebase = create a cleaner, linear history by rewriting your branch's commits.

4. What is .gitignore?

.gitignore is a file that tells Git:

"Don't track these files or folders."

For example, you might have:

project/
│
├── index.html
├── style.css
├── script.js
├── .gitignore
├── node_modules/
└── .env

You generally don't want to commit node_modules or .env.

Your .gitignore could contain:

node_modules/
.env
*.log
.DS_Store

Now Git ignores those files.

Why is .gitignore important?
1. Prevent secrets from being committed

For example:

.env

might contain:

API_KEY=abc123
DATABASE_PASSWORD=secret

You don't want that pushed to GitHub.

2. Avoid unnecessary files

For Node.js projects:

node_modules/

can contain thousands of files and can be recreated using:

npm install

So there's usually no reason to commit it.

3. Ignore generated files

For example:

*.log
dist/
build/

depending on your project.

5. What does git stash do?

git stash temporarily saves your uncommitted changes so you can have a clean working directory.

Imagine you're working on:

feature-login

You have changed:

login.html
login.css
login.js

But you haven't finished.

Suddenly, you need to switch branches:

git checkout main

Git might prevent you from switching if your changes conflict.

Instead, you can do:

git stash

Your changes are temporarily stored, and your working directory becomes clean.

You can then switch branches:

git checkout main

Do whatever you need to do.

Then return:

git checkout feature-login

And restore your changes:

git stash pop

Your changes come back.

Common stash commands
Save changes
git stash
See your stashes
git stash list

You might see:

stash@{0}: WIP on feature-login
stash@{1}: WIP on homepage
Restore the latest stash and remove it from the stash list
git stash pop
Restore without removing it
git stash apply
Delete a stash
git stash drop
Example workflow

Imagine you're working on a feature:

main
  │
  └── feature-login

You've made changes but aren't ready to commit.

git status

You can temporarily save them:

git stash

Switch to main:

git checkout main

Fix something:

git add .
git commit -m "Fix navigation bug"

Return to your feature:

git checkout feature-login

Restore your work:

git stash pop

Continue working.
